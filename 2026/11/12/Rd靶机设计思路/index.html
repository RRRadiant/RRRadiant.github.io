Rd 靶机设计思路

发表于2026-11-12|更新于2026-11-12|靶场
|浏览量:

Rd 是我做的第一台 Linux 靶机，就是想尝试一次制作靶机，所以整体链条没有做得很长，同时也让 AI 帮助了我。刚开始的想法其实很简单：入口设计的是在 Web 端通过 Redis 未授权访问，然后提权是在 GitHub 上找了一个项目部署，通过 FileBrowser 加 TOTP 进行提权，第一个版本初步做下来感觉有点容易，于是设计了一个假终端迷惑选手，同时加上了一个 .git 泄漏给入口设置了一些障碍。

这台靶机在 MazeSec 的原创靶机库中，靶机名字是 Rd。

入口：git 泄漏

对外主要是 Web。首页我做成了一个开发者博客的样子，上面放了一些不是很起眼线索，例如“Redis做缓存”以及存在定时任务，入口是 .git 泄漏，把仓库拉下来之后，能在历史记录里看到 radiant 的密码。我后来又补了一个路由说明，指向两个内部页面。

其中一个是假终端。我做成了看起来像已经拿到控制台的样子，目录也尽量跟真机对上，但是什么都执行不了，用来把人往旁边带一下。前端是自己写的，看上去像真 shell，其实命令没有真正在跑。

拿 shell：先走 SSRF，再打 Redis

Redis 没有配密码，但是服务在回环上，外面直接连不上，所以要先从 Web 这边走到内网。

git 里指向的那个链接预览，用 url 参数去拉页面。这里对主机名有一层过滤，会拦 localhost 和 127.0.0.1，不过只是简单的字符串匹配。绕过去之后就可以通过 Redis 做未授权写入 webshell，然后反弹拿到 shell。

密码虽然已经泄漏了，这一步还是要先打通，不能直接去提权。而且这份密码也不能拿来 SSH 登录，sshd 里我对 radiant 做了限制，认证能过，但会话会马上被关掉，只能拿到 shell 之后在本地 su。这也是我设置的一个障碍，不能直接进行 SSH 连接。

提权：FileBrowser 加 TOTP

提权我放在 FileBrowser Quantum 上。它以 root 跑，目录范围是整台机器，拿到后台就能读写系统里的文件。这个服务也只监听回环，所以还是要先有 shell，再在内网里找到它。

登录不是用 Linux 那个用户的密码，账号是 admin，而且还要过 TOTP，少一样都进不去。我想试一下把双因子真正用上。

最后

第一次做靶机，我感觉最容易忽略的是封版，后来也确实留下了几条非预期。

家目录里的命令历史和哈希没清干净。历史里几乎就是一份提权过程，哈希拿去破解之后，FileBrowser 的登录密码就有了，设计里要选手自己找密码的那一步就被绕过去了。

配置文件和数据库的权限也没收紧，Web 用户直接能读到解开 TOTP 要用的内容。双因子本来应该是拿到 shell 之后还要再过的一关，权限一松，就变成了读文件。

还有一个我一开始没注意到的：这个 FileBrowser 只用登录密码就能把 TOTP 重置掉，双因子会被绕过。这是项目自己的接口行为，出靶机的时候我没考虑到。

预览这边对协议限制得不够，除了打到 Redis，还能读到本机上的一些文件。Web 根目录里也直接放着路由说明，.git 还开了目录列表，不把仓库完整拉下来也能摸到隐藏路径。

这些都是第一次做才踩到的。再封一版的话，历史和临时文件要清干净，权限要收紧，双因子被重置这件事也要一起处理。
